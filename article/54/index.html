为什么 TrendRadar 的社交热榜满足不了技术博客——我的热点方案选型记录

## 我的需求 我想给我的博客集成一个热点展示功能，目标读者是**程序员群体**，关注的是： - 技术栈动态（Rust、Kubernetes、Docker 等） - AI 进展（DeepSeek、ChatGPT、开源模型等） - 真正有技术价值的内容，而不是社会热点或娱乐八卦 需求核心：**每日自动更新，零成本运行，输出要干净、结构化、可直接嵌入博客。** --- ## TrendRadar 是什么 [TrendRadar](https://github.com/pppscn/TrendRadar) 是一个 58.6K+ Star 的热点聚合工具。它从微博、知乎、B站、抖音等 11+ 平台的热榜和 RSS 源抓取内容，支持关键词过滤和 AI 摘要。 看起来很美，但我最终没有选它，原因如下。 --- ## 为什么不选 TrendRadar ### 1. 数据源决定天花板——这是最致命的问题 TrendRadar 的数据源是**社交平台热榜 + RSS**。这些平台的热榜天然偏向： - 社会热点（某明星塌房、社会新闻） - 娱乐八卦（综艺、影视、网红） - 情绪化内容（争议话题、段子、吐槽） - 营销内容（广告、软文、品牌活动） 即使它提供了强大的关键词语法过滤（`+` 必须词、`!` 排除词、正则匹配）和 AI 兴趣筛选，也只是在社交热榜的结果之上做过滤。 **源数据就不是技术内容，过滤得再好也得不到纯技术热点。** 这是一个数学问题——你不可能从微博热榜里过滤出一篇有深度的 Rust 技术分析。 ### 2. 风口炒作 ≠ 技术本身 即使严格控制关键词和白名单，社交平台上关于「技术」的内容大部分还是： - 融资新闻（某某公司获数亿融资） - 市场分析（某某赛道要火） - 大佬言论（某某说了一个观点） - 招聘行情（某某岗位薪资暴涨） 真正的技术进展——*Rust 1.96.1 发布了什么、Docker Engine 29.6.0 有哪些变更、Kubernetes 某个特性的设计决策*——在微博热榜和 B 站热门上看不到的。 **TrendRadar 搜到的「技术热点」，本质是「被大众关注的技术话题」，而非「技术本身的重要进展」。** 这两个概念有本质区别。 ### 3. AI 救不了输入质量 TrendRadar 接入了 DeepSeek/OpenAI API 做摘要和情感分析，但这需要你自己提供 API Key，按量付费。 更重要的是：**AI 执行的是对已抓取结果的二次加工**——如果爬到的东西本身就是泛娱乐内容，AI 提炼得再好也是泛娱乐。这是「垃圾进，垃圾出」的问题，不是加一层 AI 就能解决的。 ### 4. RSS 和搜索引擎的老问题依然存在 内容混杂、广告干扰、质量参差不齐、按热度排序而非按技术价值排序——这些 RSS 和搜索引擎的固有问题，在 TrendRadar 里换了一层皮仍然存在。 ### 5. 部署与成本 - TrendRadar 的 AI 功能需要 API Key，持续产生费用 - 部署流程不简单，需要配置多个数据源 - 如果我只想要技术热点，大部分配置和过滤规则其实是「反娱乐」的，需要花大量精力排除无关内容 --- ## Hotspot 的方案 **Hotspot** 的开源项目（[GitHub](https://github.com/PC2005-cloud/hotspot)），思路和 TrendRadar 完全不同： **让 AI 从搜索阶段就理解什么是「技术热点」**，而不是先爬一堆东西再过滤。 核心思路： - 用 Playwright 自动化操作 DeepSeek 免费网页版，不需要 API Key - 通过精心设计的提示词，让 DeepSeek 联网搜索时明确知道要「技术热点」 - 要求返回结构化 JSON（标题、摘要、来源、多角度观点、舆情总结） - URL 验证防 AI 编造链接（HEAD 请求检测，404 自动剔除） - 引用链接自动匹配，清理摘要标记 - 最终输出干净的 HTML 报告，可嵌入博客或部署到 GitHub Pages **关键差异**：TrendRadar 是在已有的社交数据上做减法（过滤），Hotspot 是让 AI 从搜索引擎源头做加法（直接找）。 --- ## 什么场景用什么 | 场景 | 推荐 | |------|------| | 想做泛热点聚合、追社会热点、娱乐八卦 | TrendRadar | | 想在博客展示每日新闻墙 | TrendRadar | | 程序员的博客、专注技术栈动态 | Hotspot | | 关注 AI 具体进展而不是 AI 融资新闻 | Hotspot | | 不想花钱、不想配 API Key | Hotspot | | 需要结构化数据嵌入页面 | Hotspot | --- ## 总结 不是 TrendRadar 不好，而是它解决的是**不同的问题**。 TrendRadar 解决的命题是：「现在全网什么最热？」 而我的命题是：「程序员应该关注什么？」 后者需要的不是一个社交热榜聚合器，而是一个**真正理解「技术」这个概念的搜索工具**。这就是为什么我选择了自己写 Hotspot，而不是直接用 TrendRadar——**数据源决定天花板，而我不想一开始就坐在社交热榜的井底。**

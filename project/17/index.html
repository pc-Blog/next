守护精灵

一个涵盖嵌入式硬件、网关、后端服务到前端可视化的全栈物联网项目。

项目概述

Guardian-Elf 是一套完整的物联网数据采集与远程监测系统。系统以 STM32 为主控芯片，搭载多种环境与运动传感器，通过 ESP32 网关将数据上传至 Spring Boot 后端，最终在 Vue3 搭建的 Web 管理后台进行数据可视化和设备管理。

核心流程：

传感器 → STM32 → ESP32 → WiFi → Spring Boot → 数据库 → Vue3 前端

硬件层：STM32 传感器融合采集

STM32 作为核心采集节点，通过 I2C、SPI、UART 等总线接口挂载了多种传感器，定时采集数据并合成 JSON 包通过串口发送给 ESP32。

传感器清单

传感器型号通信方式采集数据
MPU6050I2C三轴加速度（g）、三轴陀螺仪（°/s）
BMP280I2C大气压强（hPa）
AHT20I2C温度（°C）、湿度（%）
BH1750I2C光照强度（lux）
GP10UARTGPS + 北斗定位数据（经纬度、海拔、速度、航向、卫星数）
W25Q64SPI8MB Flash 存储设备序列号
OLED SSD1306I2C0.96 寸显示屏，实时展示传感器读数

OLED 多页显示

设备集成了 0.96 寸 OLED 屏幕，通过外部中断按键切换页面，共 7 个显示页：

  • 设备信息页：显示设备序列号
  • 时间信息页：GPS 授时日期与时间
  • 坐标信息页：实时经纬度与海拔
  • 运动信息页：速度、磁偏角/航向
  • 卫星信息页：GPS 与北斗卫星数量
  • 加速度页：MPU6050 三轴加速度数值
  • 角速度页：MPU6050 三轴陀螺仪数值
  • 环境信息页：光照、气压、温湿度

网关层：ESP32 数据上报

ESP32 通过串口（UART2）接收 STM32 发来的结构化数据，连接 WiFi 后以 HTTP POST 方式将数据上报至后端服务器。

通信协议

STM32 与 ESP32 之间自定义了简单的串口协议：

操作码\n数据内容\n::end::

操作码定义：

  • 0x00 —— 设备 ID
  • 0x01 —— GPS 定位数据（JSON）
  • 0x02 —— 环境数据（JSON）
  • 0x03 —— 运动数据（JSON）

数据上报 API

ESP32 向以下端点发送 POST 请求：

HTTP 路由数据内容
POST /embedded/data/GPSGPS 坐标、卫星信息、运动轨迹
POST /embedded/data/environment温度、湿度、气压、光照
POST /embedded/data/speed三轴加速度、三轴角速度

后端层：Spring Boot 数据服务

后端基于 若依（RuoYi）框架进行二次开发，在保留原有系统管理功能（用户/角色/菜单/权限）的基础上，新增了 embedded 模块专门处理物联网设备的数据接入。

@RestController
@RequestMapping("/embedded/device")
public class EmbeddedDeviceController {
    // 根据设备序列号获取设备 ID
    @RequestMapping("/id/{serial}")
    public Long getDeviceIdBySerial(@PathVariable String serial);
}

@RestController
@RequestMapping("/embedded/data")
public class AddDataController {
    // 添加 GPS 数据
    @PostMapping("/GPS")
    public AjaxResult GPS(@RequestBody Gp10Data data, Long deviceId, LocalDateTime localTime);

    // 添加环境数据
    @PostMapping("/environment")
    public AjaxResult environment(@RequestBody EnvironmentData data, Long deviceId, LocalDateTime localTime);

    // 添加运动数据
    @PostMapping("/speed")
    public AjaxResult speed(@RequestBody SpeedData data, Long deviceId, LocalDateTime localTime);
}

数据流全景

下面以一次传感器数据采集的完整链路为例，展示系统各层如何协同工作：

  1. STM32 定时采集：每隔一定时间，通过 I2C 读取 MPU6050/BMP280/AHT20/BH1750 数据，通过 UART 读取 GP10 模块的 GPS 数据
  2. 数据包装：将传感器读数组装成两个 JSON 结构体（EnvironmentData 和 MotionData），GPS 数据由 GP10 模块自行输出 JSON
  3. 串口发送：通过自定协议发送到 ESP32（UART3 → UART2）
  4. WiFi 上报：ESP32 解析操作码，通过 HTTP POST 分别上传三类数据到后端
  5. 数据入库：Spring Boot 接收 JSON，校验设备 ID 合法性，写入 location 数据库对应表中
  6. 前端展示：用户登录 Web 管理后台，在各数据页面查看实时/历史数据

写在最后

Guardian-Elf 是我从硬件选型、电路搭建、固件编写、网关开发、后端架构到前端界面的一个完整全栈项目实践。从 STM32 裸机 C 语言编程，到 ESP32 的 Arduino 开发，再到 Spring Boot + Vue3 的企业级 Web 应用，几乎涵盖了 IoT 项目的完整技术链。

项目使用双 MCU 架构（STM32 + ESP32）分离了采集和通信的职责，后端基于成熟的若依框架保证了系统管理功能的完备性和安全性，前端则充分利用了 Vue3 + Element Plus 的响应式和组件化设计。

Footer） - **`admin` 路由组** — 管理后台独立布局 - **根布局** — 全局 UI（字体、背景效果、Live2D、弹幕、主题 Provider） 组件按模块组织在 `app/_components/` 下： ``` _components/ ├── admin/ # Markdown 编辑器、日期选择器等 ├── article/ # 文章卡片、TOC、导航、内容渲染 ├── auth/ # GitHub 登录按钮 ├── comment/ # Giscus + 评论表单 ├── common/ # 搜索栏、分页、设置面板、主题切换等 ├── effects/ # 萤火虫、樱花、动态草地 └── layout/ # Header、Footer、音乐播放器、浮动导航等 ``` ### 数据流 系统支持两种运行模式： **实时模式（Docker）：** ``` 浏览器 → Next.js → 后端 API → PostgreSQL + Redis + MinIO ``` **静态模式（GitHub Pages）：** ``` 后端 API → 同步脚本 → GitHub data 分支 → CI/CD 构建 → gh-pages 分支 → 浏览器（读取本地 JSON） ``` 模式通过 `lib/static-data.ts` 自动检测：检查 `/data/index.json` 是否存在，存在则走静态模式。 > 系统架构图 — 访客、Cloudflare、部署目标、数据层、CI/CD 的关系 ![image.png](/data/media/346.png) > 双模式数据流 — 实时模式（Docker） vs 静态模式（GitHub Pages）对比 ![image.png](/data/media/344.png) --- ## build:static # 产物输出到 out/ ``` CI/CD 自动化工作流（`.github/workflows/deploy.yml`）： 1. 推送 `master` 或 `data` 分支触发 Actions 2. 检出源代码 + `data` 分支的静态数据 3. 数据文件复制到 `public/data/` 4. 执行 `npm run build:static`（`NEXT_PUBLIC_IS_STATIC=true`） 5. 自动生成 CNAME（如有自定义域名） 6. 部署到 `gh-pages` 分支 ### 10.3 数据同步流水线 端到端数据流： ``` 后端数据库 → 同步脚本（GitHub Token） → GitHub data 分支（JSON + 媒体 + 音乐） ↓ 用户访问 ← GitHub Pages ← gh-pages 分支 ← CI/CD 构建 ``` 三种同步类型： - **JSON 同步** — 文章、项目、图库等结构化数据 - **媒体同步** — 上传的图片和文件（含增量检测） - **音乐同步** — 播放列表与音频文件 > 部署架构 — 端到端数据同步与部署流水线示意图 ![image.png](/data/media/372.png) ### 10.4 Cloudflare 集成

## 一、项目简介

**医知库（智疗助手）** 是一套完整的企业级智能客服问答系统，面向医疗咨询、企业业务咨询等场景，实现了用户登录、Agent 创建、知识库管理、向量检索、RAG 增强生成、SSE 流式问答的完整闭环。

系统支持多轮对话、会话记忆持久化、私有知识库语义检索、查询意图识别，可实现 **7×24 小时无人智能答疑**，降低人工客服成本的同时保证回答的专业性与可溯源性。

## 三、核心功能

### 3.1 用户认证与会话管理

基于 JWT + BCrypt 实现用户注册、登录、鉴权全流程。登录拦截器自动校验 Token 有效性（7 天免登录），ThreadLocal 传递用户上下文，前后端无缝衔接。

![image.png](/data/media/234.png)

![image.png](/data/media/235.png)

### 3.2 AI Agent 灵活配置

Agent 是系统的核心抽象，每个 Agent 代表一个智能客服实例。支持自定义：

- **系统提示词**（System Prompt）—— 定义客服角色与行为规范
- **温度参数**（0~1）—— 控制回答的随机性与创造性
- **最大记忆轮数** —— 决定对话上下文的窗口大小
- **TopK 与相似度阈值** —— 控制知识库检索的召回数量与精度
- **多知识库绑定** —— 一个 Agent 可同时关联多个向量知识库

修改配置后，系统自动重建 Agent 实例并刷新缓存，无需重启服务。

![image.png](/data/media/236.png)

![image.png](/data/media/237.png)

### 3.3 知识库构建与向量化

知识库从 PDF 文档到向量化入库的完整流水线：

```
PDF 上传 → PDFBox 分割大文件 → MinerU 云解析（文本/表格/公式/图片）
→ VLM 多模态描述图片 → 文本分句增强 → Embedding 向量化 → Redis 向量存储
```

全过程异步处理，前端可实时轮询任务进度。

![knowledge_upload_flow.png](/data/media/239.png)

**向量检索**基于 RedisSearch 的 HNSW 索引 + COSINE 相似度算法，支持自定义向量维度（512~2048），检索时采用 **父子句分割策略**——句子级检索 + 段落级返回，兼顾召回精度与上下文完整性。

![image.png](/data/media/238.png)

### 3.4 RAG 增强生成（四阶段流水线）

RAG 是整个系统的技术核心，实现了完整的四阶段流水线：

```
用户问题 → 查询扩展 → 多向量库并发检索 → 结果后处理 → 上下文增强 → LLM 生成
```

**① 查询扩展（Query Expansion）**：利用 LLM 将用户问题与对话历史结合，生成 4 个变体查询，覆盖不同表达方式和语义角度，显著提升召回率。

**② 多向量库并发检索**：自定义 `MultiVectorStoreDocumentRetriever`，突破 Spring AI 默认仅支持单向量库的限制，使用 `CompletableFuture` 并发查询 Agent 关联的所有知识库，合并排序后返回。

![vector_retrieval_flow.png](/data/media/240.png)

**③ 结果后处理**：按相似度得分降序排列，截取 TopK 文档，确保送入 LLM 的是最相关的上下文。

**④ 上下文增强**：自定义 `ContextualQueryAugmenter`，修复了 Spring AI 原生实现丢失对话历史的 Bug。将检索到的文档内容（带 `<ID>` 标签标记来源）注入结构化 Prompt 模板，保留完整的多轮对话历史，让 LLM 既能"记住上文"，又能"参考知识"。

![rag_pipeline.png](/data/media/241.png)

### 3.5 SSE 流式问答

聊天接口基于 Spring WebFlux 的 `Flux<String>` 实现 SSE（Server-Sent Events）流式输出，前端通过 Fetch API 的 `ReadableStreamDefaultReader` 逐块读取并实时渲染 Markdown。

用户可实时看到 AI 逐字生成回答的过程，而非等待完整响应，大幅提升交互体验。

![image.png](/data/media/242.png)

### 3.6 多轮对话与记忆持久化

对话记忆基于 Spring AI 的 `JdbcChatMemoryRepository`，存储在 MySQL 的 `SPRING_AI_CHAT_MEMORY` 表中。关键特性：

- 按 Agent 隔离对话上下文（Conversation ID = Agent ID）
- 可配置的最大消息窗口，超出自动滑动
- 支持单条消息删除和清空全部历史
- 对话记忆参与查询扩展与上下文增强，支持代词消解和话题追踪

![image.png](/data/media/243.png)

### 3.7 PDF 原文查看与溯源定位

前端集成了基于 `vue-pdf-embed` 的 PDF 查看器，支持：

- 虚拟滚动与懒加载（大文档秒开）
- `IntersectionObserver` 可见性检测
- 坐标框（bbox）高亮定位 —— AI 回答可精确追溯到 PDF 原文的具体位置

![image.png](/data/media/244.png)

## 五、技术亮点

### 5.1 突破 Spring AI 框架限制

Spring AI 作为较新的框架，默认行为存在诸多局限。本项目为此做了多项底层定制：

| 问题 | 解决方案 |
|---|---|
| 默认仅支持单向量库检索 | 自研 `MultiVectorStoreDocumentRetriever`，支持多库并发检索 |
| 原生 `ContextualQueryAugmenter` 丢失对话历史 | 自研 `MyContextualQueryAugmenter`，修复 Bug 并保留完整上下文 |
| 缺少多向量库结果的统一排序与截断 | 自研 `MyDocumentPostProcessor`，跨库 TopK 排序 |
| 缺少检索过程的可观测性 | 自研 `DocumentAdvisor`，拦截 Advisor 链捕获检索结果供前端展示 |

### 5.2 父子句检索策略

传统的 chunk 级别检索存在语义粒度问题——chunk 太大检索不准，太小缺少上下文。本系统创新地采用了 **父子句分割策略**：

- **子文档**：句子级别的精细切分，用于 Embedding 与向量检索
- **父文档**：段落级别的完整上下文，检索命中子文档后返回其父文档

这样兼顾了检索的精准度和回答的完整性。

### 5.3 异步知识入库流水线

大 PDF 文件的解析入库是一个耗时操作，不适合同步等待。系统设计了完整的异步流水线：

1. 前端上传文件 → 立即返回 Task ID
2. 后端异步执行：PDFBox 分页 → MinerU 云解析 → ZIP 下载 → 内容提取 → VLM 图片描述 → 文本增强 → Embedding → Redis 入库
3. 前端轮询任务状态（每 10 秒），完成后刷新列表

`ReusableMultipartFile` 将文件字节缓存到内存，解决了异步处理中原始 HTTP 请求已结束的问题。

### 5.4 查询意图隐式识别

虽然系统没有显式的意图分类器，但 `MyQueryExpander` 通过 LLM 将用户问题展开为多个变体查询，**隐式地完成了意图识别与语义消歧**——不同的查询变体覆盖了用户可能想表达的不同含义，多向量库检索自然匹配到最相关的知识。

## 六、本地运行

### 环境要求

- JDK 21+
- Maven 3.8+
- Node.js 18+
- MySQL 8.x
- Redis Stack（含 RedisSearch 模块）
- MinIO

### 后端启动

```bash
cd Spring
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.config.location=classpath:args-dev.yaml"
```

### 前端启动

```bash
cd Vue3
npm install
npm run dev
```

- 后端：`http://localhost:9016`
- 前端：`http://localhost:5173`

## 七、适用场景

- **医疗咨询**：上传医学指南、药品说明书等 PDF 构建私有知识库，AI 基于权威文献回答患者问题
- **企业业务咨询**：将产品手册、FAQ、规章制度文档向量化，构建企业内部智能客服
- **教育辅导**：上传教材、讲义，学生可针对知识点提问并获得溯源定位
- **法律合规**：上传法规文件，辅助快速查找相关条款

本项目从零搭建了一个完整的企业级 RAG 智能问答系统，涵盖了前端 UI、后端架构、AI 流水线、数据存储等方方面面。核心的 RAG 流水线经过深度定制，在查询扩展、多库检索、上下文增强等环节做了针对性的优化，解决了 Spring AI 框架的多个原生缺陷，可满足生产环境下的稳定运行需求。

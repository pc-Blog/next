分享一个我发现的免费 AI 资讯 API：AI HOT，无需注册、无需 Token、开箱即用

最近在找免费又好用的 AI 资讯数据源，试过的几个要么注册流程繁琐，要么限流严格，要么接口设计不够友好。后来发现了 AI HOT——一个中文 AI 动态聚合平台，关键是把整套 API 完全免费开放了。我花了一些时间把 8 个接口挨个测了一遍，整体体验不错，整理成这篇笔记分享出来。

AI HOT 能干嘛

简单说，它从几十个信源（官方博客、公众号、技术社区、论文平台、社交媒体）中抓取 AI 相关内容，经过人工与算法筛选、评分、归类之后输出。你不需要自己去盯一堆信息源，一个 API 就解决了。

更让我惊喜的是，它不只是"搬运新闻"——每条内容都有质量评分和分类标签，同一个事件的多篇报道会自动串成「故事线」，还能 AI 生成事件综述。这些能力全部通过 8 个免费接口开放了出来。

值得推荐的理由

完全免费，零门槛。 不需要注册、不需要 API Key、不需要验证手机号。curl 就能通，对个人开发者和独立项目非常友好。

前端直接调，不用搭代理。 CORS 头配得整整齐齐，fetch 直连就行。之前做个小工具要么得写后端转发、要么被跨域卡脖子，这个完全没有这个问题。

精选 + 全量两种模式。 mode=selected 是人工筛选过的高质量内容，mode=all 是所有收录条目。我一般先用 selected 展示，搜不到的时候自动切 all 兜底，挺实用的。

分类很细。 每条内容标了分类：ai-models（模型发布）、ai-products（产品工具）、industry（行业动态）、paper（论文）、tip（技巧观点）。想只看某个方向直接 category= 过滤就行。

热点和故事线是亮点。 hot-topics 接口能拿 Top 10 热点排行，每个热点背面都有一条 Story——聚合所有来源报道、逆序时间线、AI 综述，而且综述会随着新报道自动更新。做个"事件来龙去脉"页面很方便。

增量同步设计得很讲究。 snapshot + changes 这对接口组了一套完整的同步协议：首次拉全量，之后 cursor 增量跑，cursor 还不会过期。离线几天回来照样续得上，这个设计挺用心的。

接口总览

Base URL：https://aihot.virxact.com，全是匿名 GET，不需要鉴权。

接口干嘛用的
/api/v1/items最近 AI 条目，用得最多的一个
/api/v1/hot-topicsTop 10 热点排行
/api/v1/stories/{publicId}事件故事线 + AI 综述
/api/v1/dailies日报归档目录
/api/v1/dailies/latest最新一期日报
/api/v1/dailies/{date}指定日期的历史日报
/api/v1/selected/snapshot精选全量快照（首次同步用）
/api/v1/selected/changes精选增量变更（持续同步用）

下面是我挨个实测的记录。

接口实测

1. items — 获取最近 AI 条目

这个接口我最常用，拿来做 Feed 流、最新动态 widget 都很合适。仅覆盖最近 7 天。

常用参数：

参数说明
modeselected（精选）或 all（全量），默认 selected
category分类过滤：ai-models / ai-products / industry / paper / tip
window24h 或 7d，默认 7d
q关键词搜索（2-200 字符）
limit1-100，默认 50
bytimeline（AI HOT 收录时间）或 published（原文发布时间）

看过去 24 小时精选：

curl "https://aihot.virxact.com/api/v1/items?mode=selected&window=24h&limit=10"

返回长这样（截首条）：

{
  "items": [
    {
      "title": "Video-DeepResearch：迈向下一代多模态深度研究智能体",
      "originalTitle": "Video-DeepResearch： Towards the Next-Generation...",
      "summary": "Video-DeepResearch 将多模态智能体从静态图像扩展到连续视频流…",
      "source": { "name": "HuggingFace Daily Papers（社区热门论文）" },
      "links": {
        "aihot": "https://aihot.virxact.com/items/...",
        "original": "https://arxiv.org/abs/2608.03979"
      },
      "category": "paper",
      "score": 74,
      "selected": true
    }
  ],
  "page": { "count": 10, "hasMore": true, "nextCursor": "..." }
}

几种我常用的变体：

# 只看模型发布
curl ".../api/v1/items?category=ai-models&window=7d&limit=10"

# 搜 OpenAI 相关内容
curl ".../api/v1/items?q=OpenAI&window=7d&limit=5"

# 全量模式（含未精选条目）
curl ".../api/v1/items?mode=all&window=24h&limit=10"

一个小技巧：如果 selected 模式搜不到关键词，自动切 all 再查一次——冷门话题往往只在全量池里有。

2. hot-topics — 当前热点 Top 10

这个接口零参数，直接调就行：

curl "https://aihot.virxact.com/api/v1/hot-topics"

返回的就是此刻 AI 圈讨论最多的 10 件事，按覆盖来源数和讨论热度排名。我写这篇时 Top 3 是：

  1. 🔥 字节 SeedRealtime 音视频全双工大模型
  2. 🔥 NVIDIA Alpamayo 2 Super 开放商用
  3. 🔥 腾讯混元 Hy ASR 3.0 语音识别

每条热点会告诉你覆盖了多少信源、哪些来源在报道，还有个 links.story 指向事件页。⚠️ 但注意，这个链接是人读的网页，别直接当 API 调——要取里面的 publicId 去调 stories 接口。

3. stories — 事件故事线

从 hot-topics 拿到的 links.story URL 里提取末尾的 publicId：

curl "https://aihot.virxact.com/api/v1/stories/abba2373-a7b7-4d0b-a324-4556c99ee019"

返回内容包括：

  • 事件状态（active 还在演化 / settled 已完结）
  • AI 生成的综述（随新报道自动更新）
  • 最新进展一句话摘要
  • 逆序的报道时间线，每条带原文链接
  • 同故事线的前置/后续事件、相关事件

这个接口的设计我很喜欢——拿来做"XX 事件的来龙去脉"页面非常方便。

4-6. 日报三件套

日报每天北京时间 08:00 发布，有三个接口覆盖：

日报归档目录（哪天有日报一目了然）：

curl "https://aihot.virxact.com/api/v1/dailies?limit=5"

最新日报（每天 08:00 后调一次就行）：

curl "https://aihot.virxact.com/api/v1/dailies/latest"

返回按「模型发布」「产品更新」「行业动态」「技巧观点」分板块组织的完整内容。

历史日报（指定日期，不可变，可无限缓存）：

curl "https://aihot.virxact.com/api/v1/dailies/2026-08-04"

7-8. 精选同步套装

如果你要维护一个本地 AI 资讯数据库，这对接口是核心。

snapshot 一次性拉全量：

curl "https://aihot.virxact.com/api/v1/selected/snapshot?fields=minimal&limit=1000"

逐页遍历直到 hasMore 为 false，保存第一页的 cursor 值。

changes 增量同步：

curl "https://aihot.virxact.com/api/v1/selected/changes?cursor={你的cursor}&limit=100"

返回 upsert（新增/更新，带完整数据）和 remove（删除，只给 id）。cursor 不会过期，离线几天照样接得上。

收到 409 就重新 snapshot 走一轮。

几个调用小贴士

善用 ETag。 所有接口都支持，首次拿到 ETag 记下来，下次带上 If-None-Match，内容没变就返回 304 空响应，省流量也友善。

别刷太狠。 items 最少 60 秒一次，hot-topics 300 秒，dailies/latest 每天 08:00 后一次就够了。被限流了就按 Retry-After 头部的时间等。

错误格式统一。 所有错误都是 application/problem+json，requestId 可以拿去排查。

API 与官网的功能差异

实际使用下来，API 并未覆盖官网的全部能力，有几点值得提前了解：

关键词搜索的精度不同。 官网的搜索看起来做了更精准的匹配和排序，搜"DeepSeek"返回的基本都是直接相关的条目；而 API 的搜索是子串匹配，q=DeepSeek 会命中所有标题或正文含 "Deep" 的条目（比如 Video-DeepResearch），搜索结果中经常混入无关内容。搜高频词（如 OpenAI）时尤甚——很多条目正文顺带提了一句就被命中，但标题和主题完全无关。搜冷门词时建议用 mode=all 扩大覆盖，搜高频词反而应该用默认的 selected 来减少噪音。

API 没有主题聚合页。 官网有按主题组织的页面（如 https://aihot.virxact.com/topics/deepseek），能自动聚合某个话题下的所有相关报道。API 目前没有对应的端点，只能通过 items 的关键词搜索来模拟，但效果差距明显。同样，stories 接口虽然能做事件时间线，但它只覆盖 hot-topics 里出现的热点事件，不能像官网那样为任意话题生成专题页。

日报和热点榜完全同步。 dailies/latest、dailies/{date} 和 hot-topics 这三个接口返回的数据和官网对应页面基本一致，可以放心使用。

没有周报/月报接口。 官网提供周报（/weekly）和月报（/monthly）页面，但目前 API 中没有对应的端点。

总体来说，API 适合做 Feed 流、数据同步、自动化推送这些场景；如果要的是官网那种精准搜索或主题浏览体验，现阶段还是直接访问网站更好。

我能想到的几个玩法

  • 个人 AI 资讯 Dashboard：fetch items，加个分类 Tab，半个小时就能搭好
  • 微信群/飞书机器人：每天 08:05 调 dailies/latest，格式化后推送到群里，AI 早报达成
  • RSS 生成器：snapshot 初始化 + changes 增量，输出自定义 RSS Feed
  • 热点追踪页：hot-topics + stories，做一个"AI 大事件时间线"

总结

AI HOT 这套 API 完全免费、零门槛、前端友好、接口设计合理，故事线和增量同步这些能力也看得出是认真做产品的结果，不是简单套壳的"新闻 API"。

如果你也在做 AI 相关内容的产品或个人项目，强烈建议试试看。

三、系统架构

前端架构

博客采用 Next.js 16 App Router 构建，路由分为两个主要组：

  • (main) 路由组 — 公共页面共享主布局（Header + 浮动导航 + Footer）
  • admin 路由组 — 管理后台独立布局
  • 根布局 — 全局 UI（字体、背景效果、Live2D、弹幕、主题 Provider）

组件按模块组织在 app/_components/ 下：

_components/
├── admin/       # Markdown 编辑器、日期选择器等
├── article/     # 文章卡片、TOC、导航、内容渲染
├── auth/        # GitHub 登录按钮
├── comment/     # Giscus + 评论表单
├── common/      # 搜索栏、分页、设置面板、主题切换等
├── effects/     # 萤火虫、樱花、动态草地
└── layout/      # Header、Footer、音乐播放器、浮动导航等

数据流

系统支持两种运行模式：

实时模式（Docker）：

浏览器 → Next.js → 后端 API → PostgreSQL + Redis + MinIO

静态模式（GitHub Pages）：

后端 API → 同步脚本 → GitHub data 分支 → CI/CD 构建 → gh-pages 分支 → 浏览器（读取本地 JSON）

模式通过 lib/static-data.ts 自动检测：检查 /data/index.json 是否存在，存在则走静态模式。

5.3 数据同步控制台

GitHub Pages 静态部署的核心功能：

  • GitHub Token 管理 — 输入拥有 repo 权限的 Personal Access Token
  • JSON 同步 — 将后端数据（文章、项目等）以 JSON 格式推送到 data 分支
  • 媒体同步 — 将上传的图片/文件同步到 data 分支
  • 音乐同步 — 将播放列表和音频文件同步到 data 分支
  • 实时进度显示 — 带日志输出的同步状态更新

同步流水线：

后端 API → 同步脚本 → GitHub data 分支（JSON + 媒体 + 音乐）→ CI/CD → gh-pages

数据同步控制台 — JSON/媒体/音乐三同步按钮及实时日志输出

5.4 维护工具

后台提供数据维护功能，帮助保持系统健康运行：

  • 孤立媒体清理 — 扫描 t_media 表中所有媒体文件记录，逐一检查是否被文章、项目等内容引用。未被引用的文件记录会被标记或删除，防止数据库冗余。该功能特别实用——在编辑文章时频繁上传/替换图片，很容易产生不再需要的文件残留。
  • 数据完整性检查 — 确保文章-标签关联、项目-技术栈关联等关系数据的完整性，修复可能出现的引用断裂问题。

媒体文件的实际存储（MinIO 对象存储）不受清理影响，只有数据库记录被清理。如需同时清理存储中的文件，可以手动操作 MinIO 控制台。

维护工具 — 孤立媒体扫描结果与清理操作

6.10 启动画面（Splash Screen）

页面首次加载时，会先显示一个全屏品牌闪屏动画，然后再进入主界面：

  • 品牌展示 — 居中显示博客名称「栏轩阁」和一句标语，配合毛玻璃背景和渐变色彩，营造第一印象
  • 记忆机制 — 利用 sessionStorage 标记 hasSeenSplash，同一会话内再次导航不会重复播放，只有新开标签页或刷新时才会重新出现
  • 渐隐过渡 — 闪屏完成后以 opacity 渐隐方式平滑过渡到主界面，避免生硬切换
  • 加载缓冲 — 在主界面渲染前展示闪屏，遮盖了初始加载时的布局抖动（CLS），提升了感知性能
  • 技术实现 — 通过根布局 app/layout.tsx 中的 <SplashScreen /> 组件实现，该组件在 <ThemeProvider> 内但在 #app-mount-root 之外，确保闪屏独立于主应用渲染树

与首页的动态背景轮播、粒子特效配合，启动画面构成了博客完整的开箱体验（out-of-box experience），让访客在第一次访问时就能感受到博客的设计风格。

十、部署与 DevOps

10.1 Docker 部署

# 多阶段构建
FROM node:22-alpine AS builder    # 构建阶段
FROM node:22-alpine AS runner     # 运行阶段（仅需 standalone 产物）

docker build -t blog-next .
docker run -d -p 3000:3000 --name blog-next blog-next
  • 基于 node:22-alpine，镜像体积最小化
  • Next.js standalone 输出模式（仅复制运行所需文件）
  • 后端地址通过 lib/siteConfig.ts 的 backUrl 配置

10.2 GitHub Pages 静态部署

npm run build:static    # 产物输出到 out/

CI/CD 自动化工作流（.github/workflows/deploy.yml）：

  1. 推送 master 或 data 分支触发 Actions
  2. 检出源代码 + data 分支的静态数据
  3. 数据文件复制到 public/data/
  4. 执行 npm run build:static（NEXT_PUBLIC_IS_STATIC=true）
  5. 自动生成 CNAME（如有自定义域名）
  6. 部署到 gh-pages 分支

10.3 数据同步流水线

端到端数据流：

后端数据库 → 同步脚本（GitHub Token） → GitHub data 分支（JSON + 媒体 + 音乐）
                                              ↓
         用户访问 ← GitHub Pages ← gh-pages 分支 ← CI/CD 构建

三种同步类型：

  • JSON 同步 — 文章、项目、图库等结构化数据
  • 媒体同步 — 上传的图片和文件（含增量检测）
  • 音乐同步 — 播放列表与音频文件

部署架构 — 端到端数据同步与部署流水线示意图

10.4 Cloudflare 集成

  • CDN 加速 — 全球节点缓存静态资源
  • Analytics Worker — 代理 Cloudflare GraphQL API，需配置 CF_API_TOKEN（Analytics:Read 权限）
  • Smart Placement — Worker 智能就近执行
  • 自定义域名 — 通过 wrangler.json 配置路由

十二、本地开发与定制

前置条件

  • Node.js >= 18（推荐 22）
  • npm
  • （可选）Java 21 + Maven 3.9+ + PostgreSQL + Redis + MinIO（运行后端）

安装与运行

git clone https://github.com/pc-Blog/next.git
cd next
npm install
npm run dev          # http://localhost:3000

定制指南

修改 lib/siteConfig.ts 中的配置即可：

配置项说明
title / authorName / bio站点标题、作者名、简介
blog / hasDomain站点域名
repo / repoIdGitHub 仓库信息
backUrl后端 API 地址
avatarUrl / bgImages头像和背景图
github / email / 社交链接联系方式
giscusCategory / giscusCategoryIdGiscus 评论区配置

更多自定义

  • 品牌色 — 修改 Tailwind CSS 配置文件中的颜色 Token
  • 背景图片 — 替换 public/bg/ 中的图片
  • Live2D 模型 — 替换 public/live2d-models/ 中的模型文件
  • 设计规范 — 详见 docs/STYLE-GUIDE.md（玻璃拟态 / 色彩 / 排版 / 动画）

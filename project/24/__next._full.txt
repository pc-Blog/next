2d:T1d40,## 痛点：备份很简单，但每天做就很烦

如果你有以下场景之一，你一定懂这种感受：

- **📸 照片备份** — 手机里的照片想定期推到 GitHub 私有仓库，但每次都要输一串 git 命令
- **🎮 游戏存档** — 几百 MB 的存档文件，`git push` 动不动就因为文件过大而失败
- **📝 Obsidian 笔记** — 每天写了很多笔记，想自动提交推送，但每次都要手动操作
- **⚙️ 服务器配置** — 改完 nginx 配置想备份，但不需要保留历史版本，只想存最新状态

你需要的不是 Git 本身，而是 **一个让 Git 变得无感的工具**。

---

## simple-git-backup 是什么？

[simple-git-backup](https://github.com/PC2005-cloud/simple-git-backup) 是一个**零外部依赖**的 Python 命令行工具，帮你把本地目录一键推送到远程 Git 仓库。

你只需要在 `config.json` 里配置好备份目标，剩下的交给它：

```bash
python main.py
```

选仓库 → 选操作 → 等它跑完。就这么简单。

---

## 三大备份模式，对症下药

不同于「一个策略打天下」的方案，这个工具根据不同的文件类型提供了三种 Git 策略：

### direct — 保留完整历史

适用于**照片、笔记、文档**等需要追溯变更的小文件。

每次备份都会创建一个新的 Git 提交，保留完整的修改历史。你可以随时通过 `git log` 查看每次备份了什么。

```json
{
  "name": "学习笔记",
  "path": "D:\\Obsidian\\我的笔记库",
  "remote": "git@github.com:xxx/my-notes.git",
  "mode": "direct"
}
```

### amend — 只存最新状态

适用于**配置文件、临时打包**等不需要历史版本的场景。

每次备份都用 `git commit --amend` 替换上一次提交，远程仓库始终保持只有 **1 次提交**，仓库体积最小化。

```json
{
  "name": "服务器配置",
  "path": "/etc/nginx",
  "remote": "git@github.com:xxx/server-config.git",
  "mode": "amend"
}
```

### split — 大文件自动分包

适用于**游戏存档、大型二进制文件**等超过 GitHub 限制的场景。

这是本工具**最亮眼的功能**。当你的文件超过 50MB（GitHub 免费用户的 push 限制），工具会自动将文件切成 50MB 的块，分别上传。更妙的是：

- **增量传输**：改 1KB 只重新上传 1 个块，不浪费流量
- **SHA256 校验**：每个文件存储哈希值，还原时自动校验完整性
- **完整还原**：克隆仓库后自动组装，文件分毫不差

```json
{
  "name": "游戏存档",
  "path": "D:\\Games\\存档",
  "remote": "git@github.com:xxx/game-saves.git",
  "mode": "split"
}
```

## 不止是备份：那些贴心细节

### 🧠 智能断网续传

备份到一半断网了？别慌。下次运行工具时，它会自动检测本地是否领先于远程（`is_ahead`），一旦发现有未推送的提交，**自动续推**，不会重复上传已有内容。

```python
# engine.py 中的智能续传逻辑
if git.is_ahead(target["path"], branch=br):
    log.warn("上次推送中断，正在续推...")
    rc, err = git.push(target["path"], force=True, branch=br)
```

### 🔒 不碰你的文件

工具严格遵守**只读原则**——它不会修改你源目录里的任何文件。它只在目标目录中创建 `.git/`（版本库）、`.split/`（分包缓存）和 `.gitignore`（分包模式的忽略规则），你的原始文件始终原封不动。

### ✅ SHA256 完整性校验

分包模式下，每个文件在切分时会同时计算 SHA256 哈希值并存储。还原时自动校验，确保分毫不差。

## 快速上手：从零到第一次备份

### 1. 克隆并配置

```bash
git clone https://github.com/PC2005-cloud/simple-git-backup.git
cd simple-git-backup
```

### 2. 编辑 config.json

```json
{
  "targets": [
    {
      "name": "我的照片",
      "path": "D:\\照片",
      "remote": "git@github.com:你的用户名/你的仓库.git",
      "mode": "direct",
      "branch": "main"
    }
  ]
}
```

每个备份目标包含：
- `name` — 标识名称
- `path` — 要备份的本地目录
- `remote` — 远程仓库 SSH 地址
- `mode` — 备份模式：`direct` / `amend` / `split`
- `branch`（可选）— 分支名，默认为 `main`

### 3. 运行

```bash
python main.py
```

选择仓库 → 选择「备份」→ 等待完成。

就这么简单。

## 还原备份

不管哪种模式备份的，还原都只需要一条命令（或交互菜单选「还原」）：

```python
python main.py restore
```

工具会克隆远程仓库到 `restore_data/<目标名称>/` 目录。如果是分包模式，还会自动组装文件并校验 SHA256。

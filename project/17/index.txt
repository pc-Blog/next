## 项目概述

Guardian-Elf 是一套完整的物联网数据采集与远程监测系统。系统以 STM32 为主控芯片，搭载多种环境与运动传感器，通过 ESP32 网关将数据上传至 Spring Boot 后端，最终在 Vue3 搭建的 Web 管理后台进行数据可视化和设备管理。

**核心流程**：

```
传感器 → STM32 → ESP32 → WiFi → Spring Boot → 数据库 → Vue3 前端
```

[此处插入：系统整体架构图]

## 技术栈

| 层级 | 技术选型 |
|------|----------|
| **嵌入式主控** | STM32F103C8T6（ARM Cortex-M3），基于 HAL 库 + C 语言裸机开发 |
| **物联网网关** | ESP32（Arduino 框架），使用 PlatformIO 构建 |
| **后端服务** | Java 17 + Spring Boot 3.5.4 + MyBatis + MySQL + Redis |
| **前端界面** | Vue 3 + Element Plus + Vuex + Vue Router |
| **构建工具** | STM32CubeIDE / Keil（嵌入式）、PlatformIO（ESP32）、Maven（后端）、Vite（前端） |

[此处插入：技术栈 LOGO 拼图]

## 硬件层：STM32 传感器融合采集

STM32 作为核心采集节点，通过 I2C、SPI、UART 等总线接口挂载了多种传感器，定时采集数据并合成 JSON 包通过串口发送给 ESP32。

### 传感器清单

| 传感器型号 | 通信方式 | 采集数据 |
|-----------|---------|---------|
| **MPU6050** | I2C | 三轴加速度（g）、三轴陀螺仪（°/s） |
| **BMP280** | I2C | 大气压强（hPa） |
| **AHT20** | I2C | 温度（°C）、湿度（%） |
| **BH1750** | I2C | 光照强度（lux） |
| **GP10** | UART | GPS + 北斗定位数据（经纬度、海拔、速度、航向、卫星数） |
| **W25Q64** | SPI | 8MB Flash 存储设备序列号 |
| **OLED SSD1306** | I2C | 0.96 寸显示屏，实时展示传感器读数 |

## 网关层：ESP32 数据上报

ESP32 通过串口（UART2）接收 STM32 发来的结构化数据，连接 WiFi 后以 HTTP POST 方式将数据上报至后端服务器。

### 通信协议

STM32 与 ESP32 之间自定义了简单的串口协议：

```
操作码\n数据内容\n::end::
```

操作码定义：
- `0x00` —— 设备 ID
- `0x01` —— GPS 定位数据（JSON）
- `0x02` —— 环境数据（JSON）
- `0x03` —— 运动数据（JSON）

### 数据上报 API

ESP32 向以下端点发送 POST 请求：

| HTTP 路由 | 数据内容 |
|----------|---------|
| `POST /embedded/data/GPS` | GPS 坐标、卫星信息、运动轨迹 |
| `POST /embedded/data/environment` | 温度、湿度、气压、光照 |
| `POST /embedded/data/speed` | 三轴加速度、三轴角速度 |

## 数据流全景

下面以一次传感器数据采集的完整链路为例，展示系统各层如何协同工作：

1. **STM32 定时采集**：每隔一定时间，通过 I2C 读取 MPU6050/BMP280/AHT20/BH1750 数据，通过 UART 读取 GP10 模块的 GPS 数据
2. **数据包装**：将传感器读数组装成两个 JSON 结构体（`EnvironmentData` 和 `MotionData`），GPS 数据由 GP10 模块自行输出 JSON
3. **串口发送**：通过自定协议发送到 ESP32（UART3 → UART2）
4. **WiFi 上报**：ESP32 解析操作码，通过 HTTP POST 分别上传三类数据到后端
5. **数据入库**：Spring Boot 接收 JSON，校验设备 ID 合法性，写入 `location` 数据库对应表中
6. **前端展示**：用户登录 Web 管理后台，在各数据页面查看实时/历史数据

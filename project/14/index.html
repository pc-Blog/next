SmartMall

> 从零到一，构建一个生产级微服务电商平台。 ## 项目简介 SmartMall 是一个完整的 **B2C 单商户电商平台**，采用当下主流的 **Spring Cloud Alibaba 微服务架构**，涵盖前台商城系统与后台管理系统两大模块，实现了从商品管理、用户登录、购物车、订单下单到支付回调、秒杀抢购的完整电商业务闭环。 项目不仅是一个 CRUD 集合，更着重解决了分布式场景下的**服务治理、分布式事务、高并发库存扣减、购物车合并、幂等性设计**等真实生产环境中的核心技术难题。 <!-- 预留：项目架构全景图 --> *（图片：项目架构全景图）* --- ## 技术选型 | 层级 | 技术栈 | 版本 | |------|--------|------| | 开发语言 | Java | 21 | | 核心框架 | Spring Boot | 3.5.5 | | 微服务框架 | Spring Cloud | 2025.0.0 | | 服务注册 & 配置中心 | Alibaba Nacos | 2023.0.1.0 | | 服务网关 | Spring Cloud Gateway (WebMvc) | - **统一响应体** `R`：标准化的 JSON 返回格式 - **全局异常处理**：`BaseException` + `BaseCodeEnum` 错误码体系 - **MyBatis-Plus 配置**：分页插件、乐观锁 - **Feign 配置**：请求拦截器（透传 Session）、Sentinel 整合 - **RabbitMQ 配置**：手动确认、发布确认、退货回调 - **Redis 配置**：Spring Session Redis + 分布式会话（`GULISESSION` Cookie，父域 `gulimall.com`） - **校验分组**：JSR-303 分组校验（AddGroup / UpdateGroup） - **ThreadPool 配置**：统一异步线程池 --- ## 网关路由设计 网关是整个系统的流量入口，采用了**路径路由 + 域名路由**的双重策略： - **后台管理 API**：`/api/product/**` → `lb://product`，`/api/order/**` → `lb://order`，以此类推 - **前台商城页面**：通过二级域名区分业务模块 —— `search.gulimall.com` → 搜索页，`item.gulimall.com` → 商品详情页，`auth.gulimall.com` → 登录注册页，`cart.gulimall.com` → 购物车页，`order.gulimall.com` → 订单页，`seckill.gulimall.com` → 秒杀页 所有请求统一经过 Gateway，由 Nacos 做服务发现，Sentinel 做流量防护。 <!-- 预留：网关路由图 --> *（图片：网关路由规则示意图）* --- ## 核心业务设计与技术亮点 ### 1. 商品系统 —— 三级分类 & ES 全文检索 **三级分类树**：分类采用 `parent_cid` 自关联设计，通过一次全量查询 + 内存递归组装成树形结构，并按 `sort` 字段排序。热门分类数据使用 Spring Cache（`sync = true`）缓存至 Redis，防止缓存击穿。 **SPU/SKU 模型**：遵循电商标准建模 —— SPU（标准化产品单元）描述通用属性（品牌、描述、图片集），SKU（库存量单位）承载具体销售属性（颜色、内存、价格）。商品上架时，系统将 SPU 基本信息 + 所有 SKU 数据汇总写入 Elasticsearch，同步推送至搜索服务。 **商品详情页**：使用 `CompletableFuture` 异步编排，并行加载 SKU 信息、销售属性、SPU 描述、规格参数、SKU 图片、秒杀信息等 6 个数据模块，最终 `allOf()` 统一返回，显著缩短页面响应时间。 <!-- 预留：商品详情页截图 --> *（图片：商品详情页 —— 展示 SKU 切换、属性展示、价格等信息）* ### 2. 搜索系统 —— Elasticsearch 聚合筛选 搜索服务基于 Elasticsearch 构建，支持： - **关键字高亮搜索**：`skuTitle` 字段模糊匹配，命中关键词以红色 `<b>` 标签高亮 - **多维度聚合筛选**：品牌聚合（含 Logo 子聚合）、分类聚合、属性聚合（Nested 嵌套文档），支持面包屑导航与条件移除 - **条件组合查询**：Bool Query 组合关键字、分类、品牌、属性、价格区间、库存状态，支持多字段排序与分页 <!-- 预留：搜索页截图 --> *（图片：搜索页 —— 展示筛选条件、商品列表、面包屑导航）* ### 3. 购物车系统 —— 离线购物车 & 登录合并 购物车数据完全存储在 Redis（Hash 结构），使用 `user-key` 作为临时用户标识： - **未登录用户**：通过浏览器 Cookie 存储 `user-key`（UUID，30 天有效期），购物车数据存储在 `gulimall:cart:{user-key}` 中 - **已登录用户**：购物车数据存储在 `gulimall:cart:{userId}` 中 - **购物车合并**：用户登录后，系统自动将临时购物车中的商品逐项合并到用户购物车，新商品新增，已有商品数量累加，合并完成后清除临时数据 <!-- 预留：购物车页截图 --> *（图片：购物车页 —— 展示商品列表、数量修改、选中状态）* ### 4. 订单系统 —— 分布式事务 & 最终一致性 下单流程是项目中最复杂的业务流程，涉及多个服务的协同调用： <!-- 预留：下单流程图 --> *（图片：下单流程时序图）* #### 4.1 订单确认 用户进入确认页时，系统并行异步加载四类数据： - 收货地址列表（Member 服务） - 购物车选中商品（Cart 服务） - 商品库存信息（Ware 服务） - 用户积分（Member 服务） 同时生成**幂等性令牌**（UUID），写入 Redis 并设 30 分钟过期，用于后续提交订单的防重复提交。 #### 4.2 订单提交 ``` 验证令牌（Lua 脚本原子删除） → 创建订单 & 订单项 → 验证价格 → 锁定库存（远程调用 Ware 服务） → 发送延迟消息到 RabbitMQ（超时关单） → 清除购物车 ``` **关键设计**： - **幂等性**：使用 Redis + Lua 脚本保证"验证令牌 + 删除令牌"的原子性，从源头防止重复下单 - **库存锁定**：Ware 服务采用"遍历仓库、就近锁定"策略 —— 对每个 SKU 遍历有库存的仓库列表，执行 SQL `update wms_ware_sku set stock_locked = stock_locked + #{num} where sku_id = #{skuId} and ware_id = #{wareId} and stock - stock_locked >= #{num}`，扣减成功则停止遍历 - **最终一致性**：库存锁定成功后发送 `stock.locked` 消息；订单超时后触发库存解锁，通过 RabbitMQ 保证订单与库存状态的最终一致 <!-- 预留：订单确认页截图 --> *（图片：订单确认页 —— 展示地址选择、商品清单、价格明细）* ### 5. 库存系统 —— RabbitMQ 可靠消息与解锁流程 库存的锁定与释放是分布式事务的典型场景，项目设计了一套基于 RabbitMQ 的可靠消息机制： ``` 用户下单 → 锁定库存 → 发送 stock.locked 消息（延迟队列） ↓ 订单超时未支付 → 关闭订单 → 发送 order.release.other ↓ 库存解锁（Ware 服务） ``` **解锁逻辑**：Ware 服务收到解锁请求后，查询工作单详情： - 若对应订单为 `null`（订单创建失败）→ 解锁库存 - 若订单状态为 `已取消` → 解锁库存 - 若订单状态为 `已支付` → 不解锁（正常交易完成） 消息采用手动确认模式（`basicAck` / `basicReject`），处理失败的消息重新入队，保证消息不丢失。 <!-- 预留：库存流转示意图 --> *（图片：库存锁定与释放流转图）* ### 6. 秒杀系统 —— 高并发架构设计 秒杀是电商中最具挑战性的场景，系统从多个层面做了高并发优化： #### 6.1 定时上架 通过 `@Scheduled` 定时任务，每天凌晨扫描未来 3 天的秒杀活动，将场次和商品信息预热到 Redis： - **活动场次**：`seckill:sessions:{start}_{end}` → Redis List，存储 `sessionId-skuId` - **商品详情**：`seckill:skus` → Redis Hash，Key 为 `sessionId-skuId`，Value 为 `SeckillSkuRedisTo`（含商品信息、秒杀价、随机码、信号量 key） - **库存信号量**：`seckill:stock:{randomCode}` → Redisson `RSemaphore`，初始值为秒杀库存数 #### 6.2 秒杀流程 ``` 验证活动时间 → 验证随机码（防止提前刷接口） → Redisson 信号量 tryAcquire()（原子扣减库存） → Redis SETNX 幂等占位（防重复下单） → 发送 MQ 消息 → 异步创建订单 ``` **核心优化点**： - **Redis 预热**：商品数据全量缓存，秒杀请求不穿透数据库 - **Redisson 分布式信号量**：替代数据库行锁，原子扣减，性能量级提升 - **随机码机制**：为每个秒杀商品生成 UUID 随机码，商品未到秒杀时间时不暴露秒杀接口 - **异步下单**：秒杀成功只扣减信号量 + 发送 MQ 消息，订单创建由 Order 服务异步消费完成，快速响应客户端 - **Sentinel 限流**：在查询秒杀商品接口上配置 Sentinel 流控规则，保护下游服务 <!-- 预留：秒杀页面截图 --> *（图片：秒杀页面 —— 展示倒计时、商品信息、抢购按钮）* ### 7. 认证系统 —— 分布式会话 & 社交登录 认证中心统一管理用户身份，支持多种登录方式： - **账号密码登录**：调用 Member 服务验证，成功后写入 Session - **短信验证码登录**：60 秒防刷限制，验证码存入 Redis（5 分钟过期），验证后删除（一次性令牌） - **社交登录（OAuth2.0）**：已集成微博、GitHub 第三方登录回调 **分布式会话**：基于 Spring Session + Redis 实现，所有服务共享 Session。通过配置 `GULISESSION` Cookie（domain: `gulimall.com`，path: `/`），确保用户在 `auth.gulimall.com` 登录后，在 `cart.gulimall.com`、`order.gulimall.com` 等子域名下均可识别登录状态。 每个需要登录态的服务通过自定义 `LoginUserInterceptor`，从 Session 中提取用户信息并存入 `ThreadLocal`，业务代码通过 `LoginUserInterceptor.threadLocal.get()` 直接获取。 <!-- 预留：登录页截图 --> *（图片：登录注册页）* ### 8. 支付系统 —— 支付宝 & 微信支付 集成支付宝沙箱环境与微信支付 BestPay SDK： - **支付宝**：PC 网站支付（`AlipayTemplate`），下单 → 生成支付表单 → 同步跳转 + 异步通知 - **微信支付**：Native 支付，下单 → 生成支付二维码 → 异步回调通知 支付异步通知接口验证签名后，更新订单状态为"已支付"，并保存支付交易流水（`PaymentInfoEntity`）。 <!-- 预留：支付页截图 --> *（图片：支付页 —— 展示支付方式选择、订单金额）* --- ## 消息驱动架构 RabbitMQ 是整个系统异步通信的核心，承担了订单超时关单、库存释放、秒杀异步下单等关键任务： | 交换机 | 路由键 | 队列 | 用途 | |--------|--------|------|------| | `order-event-exchange` | `order.create.order` | `order.delay.queue` | 订单创建后延迟检查（死信转正常队列） | | `order-event-exchange` | `order.release.other` | `stock.release.stock.queue` | 订单关闭后通知库存解锁 | | `order-event-exchange` | `order.seckill.order` | `order.seckill.order.queue` | 秒杀成功后异步创建订单 | | `stock-event-exchange` | `stock.locked` | `stock.delay.queue` | 库存锁定后延迟检查解锁 | <!-- 预留：RabbitMQ 消息流转图 --> *（图片：RabbitMQ 消息流转图 —— 展示交换机、队列、消费者关系）* --- ## 后台管理系统 基于**人人开源（Renren）**框架搭建，提供完整的可视化管理后台： - **商品管理**：分类维护、品牌管理、属性分组、SPU/SKU 管理、商品上架 - **订单管理**：订单查询、订单详情、退货处理 - **营销管理**：优惠券管理、满减规则、阶梯价格、会员价格、首页广告、秒杀活动配置 - **会员管理**：会员列表、会员等级 - **仓储管理**：仓库管理、库存查询、采购单管理 - **系统管理**：用户管理、角色权限、菜单配置 <!-- 预留：后台管理系统截图 --> *（图片：后台管理系统 —— 商品管理页面）* *（图片：后台管理系统 —— 秒杀活动配置页面）* --- ## 分布式治理 ### 服务发现 & 配置中心 —— Nacos 所有微服务启动时向 Nacos 注册，Gateway 通过服务名（`lb://service-name`）做负载均衡转发。公共配置（数据源、Redis、RabbitMQ、Sentinel 等）通过 Nacos Config 统一管理，支持动态刷新。 ### 熔断降级 —— Sentinel 在 Feign 调用、秒杀查询等关键链路上配置 Sentinel 流控与降级规则，当下游服务不可用时快速失败，防止级联雪崩。 ### 链路追踪 —— Zipkin 集成 Micrometer Tracing + Zipkin Brave，使用 B3 传播协议，实现跨服务的调用链追踪与性能分析。 ### 分布式事务 项目未引入 Seata 等重型分布式事务框架，而是通过 **RabbitMQ 最终一致性** + **本地事务** 的组合方案，以更轻量的方式实现跨服务数据一致性： - 订单创建 → 库存锁定 → MQ 延迟消息 → 超时回滚 - 库存锁定 → MQ 消息 → 订单取消 → 库存解锁 --- ## 项目部署 ### 依赖中间件 | 中间件 | 端口 | 用途 | |--------|------|------| | MySQL | 53306 | 数据持久化（6 个业务库） | | Redis | 56379 | 缓存、分布式会话、秒杀信号量 | | Nacos | 58848 | 服务注册与配置管理 | | RabbitMQ | 55672 | 异步消息 | | Elasticsearch | - | 商品全文检索 | | MinIO | 59000 | 图片/文件存储 | | Sentinel Dashboard | 58858 | 流量监控面板 | ### 启动顺序 ``` 1. 启动所有中间件（MySQL、Redis、Nacos、RabbitMQ、Elasticsearch、MinIO） 2. 启动 common 模块（install 到本地仓库） 3. 启动 Gateway 4. 依次启动各业务服务（product → coupon → member → ware → search → auth → cart → order → seckill → third-party） 5. 启动 renren-fast（后台管理 API） 6. 启动前端项目（npm run dev） ``` <!-- 预留：Nacos 控制台截图 --> *（图片：Nacos 服务列表 —— 展示所有已注册的微服务）* <!-- 预留：Sentinel 控制台截图 --> *（图片：Sentinel 监控面板）* --- ## 项目展望 SmartMall 未来可在以下方向持续演进： - **容器化部署**：编写 Dockerfile 与 Kubernetes 编排脚本，实现一键部署 - **CI/CD 流水线**：接入 Jenkins 或 GitHub Actions，实现自动化构建与发布 - **读写分离**：MySQL 主从复制 + ShardingSphere，应对日益增长的数据量 - **服务网格**：引入 Istio，将流量管理、安全、可观测性下沉至 Sidecar - **日志中心**：ELK（Elasticsearch + Logstash + Kibana）统一日志采集与检索 - **灰度发布**：结合 Nacos 权重路由 + Gateway 流量染色，实现平滑上线 - **响应式编程**：WebFlux 替代 WebMvc，提升网关与高并发服务吞吐量 --- ## 写在最后 SmartMall 是我对微服务架构的一次完整实践，从服务拆分、远程调用、消息驱动到分布式治理，力求覆盖一个生产级电商系统所需的核心技术点。项目的初衷不是做一个"能用就行"的 demo，而是在每个技术决策上追问"为什么"——为什么用最终一致性而不是强一致性？为什么用 Redis 分布式信号量而不是数据库行锁？为什么购物车需要离线与在线合并？
